## 毛玻璃方案改为系统级 Acrylic

**问题**：原实现用 `transparent: true` + CSS `backdrop-filter: blur()`。
backdrop-filter 在 WebView2 里只能作用于窗口内部元素，**透不到系统窗口层**，
模糊的是窗口后面的桌面——纯色壁纸下完全没有层次感，观感很差。

**结论**：真正的"实时模糊"必须走 Windows DWM 的系统级材质（Acrylic / Mica），
而不是 CSS。官方配置文档明确：windowEffects **requires the window to be transparent**。

### 改动三处
1. `src-tauri/tauri.conf.json`：窗口加 `windowEffects: { "effects": ["acrylic", "mica"] }`
   - `acrylic` = DWM 实时高斯模糊，不依赖壁纸，Win10/11 支持 → 首选
   - `mica` 仅作 fallback（Win11 专属，只取壁纸色、**不实时模糊**）
2. `src/styles.css`：删除 `.glass-root` 的 `backdrop-filter`（否则与 acrylic 双重模糊），
   `--bg-root` 透明度 0.72 → 0.52，让系统模糊透出来
3. `src/main.ts`：`init()` 里加运行时 `appWindow.setEffects({ effects: ['acrylic','mica'] })` 双保险

### 踩坑
- `windowEffects.color` 字段写 `[16,18,23,0.6]` 触发 schema 校验失败：
  `is not valid under any of the schemas listed in the 'anyOf' keyword`。
  color 只是 tint 微调且对 Win11 无效果，直接去掉即可，不要混写 int 和 float。

### 效果参数（后续微调入口）
- `src/styles.css` 的 `--bg-root: rgba(13, 15, 19, 0.52)` —— 调大更实、调小更透
- effects 顺序决定优先级，官方说明 "Conflicting effects will apply the first one and ignore the rest"

### 已知限制
- Acrylic 在 Win11 build 22000 上拖动/缩放窗口时性能较差（官方注明），属系统层面问题
- 视觉效果需在用户机器上实际运行确认，构建环境无法验证

- 绿色 exe：`src-tauri/target/release/onekey-updater.exe` 4.0 MB
- NSIS 安装包：`src-tauri/target/release/bundle/nsis/一键更新_0.1.0_x64-setup.exe` 2.1 MB

## 第二轮修复：winget 解析 / 文字渲染 / 多线程与 GPU（09-09 13:20）

### 1. winget 解析失败（根因不在解析代码）
报错 `invalid number at line 1 column 4`。
真实原因：**winget v1.30.130-preview 的 `upgrade` 子命令不支持 `--output json`**，
传了会输出中文帮助文本，而帮助文本里的 `[[-q] <query>...]` 被 extract_array 当成 JSON 数组抠出，
`-q` 不是数字 → 报错。原 PowerShell 脚本也踩了同一个坑。

修复：
- 命令改为 `winget upgrade --accept-source-agreements --disable-interactivity`（不再传 --output）
- 保留 JSON 路径 `try_json()` 供未来版本；当前走表格解析 `parse_table()` + `parse_row()`
- **关键陷阱**：名称过长时 winget 会压缩列，名称与 ID 之间可能只剩 **1 个空格**
  （例：`Microsoft Windows Desktop Runtime - 8.0.19 (x64) Microsoft.DotNet.DesktopRuntime.8`），
  按空格切列会整体错位。
  解法：**从行尾倒序取 token** —— 源/可用版本/版本/ID 固定取末尾 4 个，剩下全是名称。
- 加了 4 个单元测试（`cargo test --lib` 全绿），含压缩列、逗号括号名称、总结行过滤

### 2. 文字渲染
- `--bg-root` 0.52 → 0.44（更透，让 acrylic 模糊显现）
- 文字提亮：`--text` #e9ecf1 → #f4f7fa，dim/faint 同步提高
- 加 `text-rendering: optimizeLegibility` + `-moz-osx-font-smoothing`
- 关键文字加 `text-shadow: 0 1px 2px rgba(0,0,0,.55)` 提升半透明背景上的可读性

### 3. 多线程
- `util::par_map()`：受限并发（默认 8）的并行 map，Arc 共享输入 + 分块线程
- `check_updates`：四个源从串行改为 `std::thread` 并行（各自拉子进程）
- npm 的 dev/beta tag 探测（每包 2 次 `npm view` 网络调用）也走 par_map 并行

### 4. GPU 加速
- `main.rs` 在 `run()` 前设置 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`：
  `--enable-gpu-rasterization --ignore-gpu-blocklist --enable-zero-copy --enable-native-gpu-memory-buffers --disable-features=CalculateNativeWinOcclusion`
- CSS：`.glass-root` 加 `transform: translateZ(0)` 提升为独立合成层；
  滚动容器 `.list-scroll` / `.log-body` 加 `contain: paint` 限制重绘范围

## 第四轮：设置改独立子窗口 + 修 hidden 失效 bug（09-09 13:50）

### 【重要 bug】HTML `hidden` 属性被 CSS `display` 覆盖
现象：检查完更新后"点击「检查更新」开始扫描"不消失；设置界面一直占布局空间。
根因：`.pane-empty{display:grid}` / `.progress-wrap{display:flex}` / `.view{display:flex}`
等**作者样式的 display 优先级高于 UA 样式的 `[hidden]{display:none}`**，
导致 `el.hidden = true` 完全无效。
修复：全局加 `[hidden] { display: none !important; }`。
**以后任何用 hidden 控制显隐的元素，只要 CSS 里设过 display，都必须有这条兜底。**

### 设置改为独立子窗口
- 新增 `settings.html` + `src/settings.ts`（设置窗口独立页面）
- 新增 `src/theme.ts` 抽出共享主题逻辑（ThemeState / PRESETS / applyTheme / load / save / applyWindowEffects）
- `vite.config.ts` 配 rollupOptions.input 多页面：main=index.html, settings=settings.html
  （相对路径字符串即可，type:module 下不能用 __dirname）
- Rust 侧加 `open_settings` command，`WebviewWindowBuilder` 动态创建/复用 label="settings"
  窗口（decorations:false + transparent:true 在 Rust 设置；Acrylic 由前端自己调）
  —— 需要 `use tauri::Manager;` 才能用 `get_webview_window`
- 主题跨窗口同步：设置窗口改完 `emit('theme-changed', theme)`，主窗口 `listen` 后 applyTheme
- `capabilities/default.json`：去掉 `windows:["main"]` 限制（改为应用全部窗口），
  加 `core:event:allow-emit`

## 第六轮：主窗口卡死 / 无法拖动 修复（09-09 15:30）

### 症状
用户报告「无法拖动，主窗口卡死，无响应」。

### 排查过程
1. 实测新 exe：主进程 `Responding=True`，WebView2 进程 CPU 正常 —— 卡死是**特定条件触发**，非启动即死。
2. 关键发现：系统里堆了 **5 个 `onekey-updater.exe` 僵尸实例**（"打开设置卡死"期间反复启动残留），
   互相竞争资源。清理后正常。
3. 更深的线索：**旧版本会 fork 出自己的子进程**（主进程 11112 → 子进程 45940），
   该子进程成为"拒绝访问、内存 0MB、8 分钟不回收"的僵尸。定位到旧版 `tauri.conf.json` 里
   notify 窗口配了 `focus:false` + `alwaysOnTop` + `windowEffects(acrylic)`，这个组合触发了异常进程行为。

### 修复（4 处）
1. **`send_notification` 改 `spawn_blocking`**：原来 async command 内**同步**调 PowerShell（原生通知），
   阻塞 tokio worker，多个并发会耗尽线程池 → 主窗口无响应。现丢进 spawn_blocking。
2. **`show_native` PowerShell 重写**：原脚本 `ShowBalloonTip` 后 100ms 就 `Dispose()`，气泡不显示且
   Dispose 等待消息循环会卡；改为 `DoEvents()` 空转 3 秒再 Dispose。
3. **notify 窗口去 acrylic + 去 `focus:false`**：消除第三个系统级模糊窗口的 DWM 压力，
   并规避 `focus:false` 触发的异常 fork。
4. **`setupProximityZoom` 缓存优化**：原实现每次 mousemove 都 `querySelectorAll` + 逐个
   `getBoundingClientRect()`（强制重排），列表一长就卡顿；改为缓存 `verCache`（元素+坐标），
   仅在滚动/resize/列表重建时重算。

### 验证
新版本启动后：不 fork 子进程、CPU 累计 0.5s（无死循环）、33 秒稳定运行、WebView2 进程健康。

### 遗留
PID 45940 是旧版 fork 出的僵尸进程，`拒绝访问`无法终止（`Stop-Process`/`taskkill /F` 均失败），
内存 0MB 不占资源、不锁 exe，但需**重启系统**才能回收。构建前若再遇 `os error 5`，
先 `Get-Process onekey-updater` 确认有无残留实例。
